# Sim Story Universe 🎀

Нежная интерактивная энциклопедия Sims-династии: персонажи, журнальные главы, семейное древо, отношения, заметки, теги и резервные копии.

## Что уже реализовано

- Главная страница со статистикой, последними главами, избранными персонажами и случайными цитатами.
- CRUD для персонажей, историй, отношений и идей.
- Профили персонажей с портретом, биографией, чертами, профессией, мечтами, страхами и секретами.
- Редактор историй из блоков: абзац, подзаголовок, цитата и изображение с подписью.
- Семейное древо с перетаскиванием карточек, масштабом и линиями разных типов.
- Поиск по биографиям, историям, тегам и отношениям.
- Импорт и экспорт архива в JSON. Экспорт пытается встроить доступные фотографии в резервный файл.
- Адаптивная вёрстка для телефона и компьютера.
- Публичный режим чтения и вход владельца через Supabase Auth.

## Демо-режим

Если переменные Supabase не заданы, приложение запускается с примерными персонажами и главами. Все правки в этом режиме сохраняются только в `localStorage` текущего браузера и не синхронизируются с другими устройствами. Это сделано для предварительного знакомства с интерфейсом. После подключения Supabase удалённые данные будут загружаться из облака.

## 1. Создай проект Supabase

1. Перейди на <https://supabase.com/> и создай новый проект.
2. Дождись окончания настройки базы данных.
3. Открой **Project Settings → API** (в некоторых версиях панели URL и ключи находятся в **Project Settings → API Keys**).
4. Скопируй **Project URL** и публичный **anon / publishable key**. В браузерное приложение нельзя помещать `service_role` / secret key — он даёт повышенные привилегии и не должен быть доступен посетителям.

## 2. Создай таблицы и Storage

1. В панели Supabase открой **SQL Editor → New query**.
2. Скопируй весь файл `supabase/schema.sql` из этого проекта, вставь и выполни.
3. SQL создаёт таблицы `characters`, `stories`, `relationships`, `family_tree`, `ideas`, `tags`, политики RLS и публичный Storage bucket `photos`.
4. Проверь в **Storage** наличие bucket `photos`.

В bucket хранятся публично читаемые изображения. Загружать, обновлять и удалять файлы могут только авторизованные пользователи. Публичная ссылка на фото означает, что посетитель, получивший URL, сможет открыть изображение.

## 3. Создай только свой аккаунт редактора

1. В Supabase открой **Authentication → Users → Add user** и вручную создай аккаунт владельца (email и надёжный пароль).
2. В **Authentication → Settings / Providers → Email** отключи публичную регистрацию (**Allow new users to sign up / Enable sign ups**). Интерфейс сайта не содержит кнопки регистрации.
3. Не создавай дополнительные аккаунты для посторонних. SQL допускает запись для `authenticated`, а не только конкретного user ID; поэтому ручное создание аккаунта и отключение sign-up — часть конфигурации безопасности.
4. Настрой также **Authentication → URL Configuration**: добавь домен сайта в **Site URL** и разрешённые **Redirect URLs** после публикации.

Таблицы разрешают публичный `SELECT`, а `INSERT`, `UPDATE` и `DELETE` — только после входа. Для историй публичное чтение ограничено строками `published = true`; после входа владелец может читать и черновики.

## 4. Запусти проект локально

Нужен Node.js 20 или новее.

```bash
npm install
cp .env.example .env.local
```

Открой `.env.local` и заполни значения:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY
```

Запусти в терминале:

```bash
npm run dev
```

Vite покажет адрес для предварительного просмотра. Переменные с префиксом `VITE_` попадут в клиентскую сборку, поэтому здесь должен быть только публичный anon/publishable key. Правила RLS обязательны; ключ не заменяет контроль прав в базе.

## 5. Публикация на Netlify

1. Загрузи весь проект в собственный GitHub-репозиторий, кроме `.env.local` (он исключён в `.gitignore`).
2. В Netlify выбери **Add new site → Import an existing project** и подключи репозиторий.
3. Build command: `npm run build`; Publish directory: `dist`.
4. В **Site configuration → Environment variables** добавь `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
5. Запусти deploy. Если меняла переменные окружения после публикации — сделай новый deploy.
6. Добавь опубликованный домен в Supabase Auth URL Configuration.

Файл `netlify.toml` уже содержит настройки сборки.

## 6. Или публикация на Vercel

1. Импортируй репозиторий в <https://vercel.com/>.
2. Выбери Vite или используй настройки из `vercel.json`.
3. Добавь те же переменные окружения `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в настройках проекта.
4. Нажми Deploy и добавь домен в Supabase Auth URL Configuration.

## 7. Как пользоваться

- В «Персонажах» нажми **Новый персонаж**, заполни анкету и добавь портрет.
- В «Историях» создай главу и добавляй блоки текста, заголовки, цитаты и фото с подписями в нужном порядке.
- В «Древе семьи» перетаскивай карточки персонажей. Колесо мыши при зажатом Ctrl/⌘ меняет масштаб; кнопки масштаба доступны над холстом. Нажми на линию, чтобы открыть описание связи.
- Создавай связи через «Отношения» или кнопку на древе. Тип отношения определяет цвет и стиль линии.
- В «Идеях» храни будущие сцены, конфликты, диалоги и повороты сюжета.
- В «Поиске и тегах» можно искать фрагменты анкет и глав или нажать на тег.
- В меню «Данные и копии» скачай JSON для резервного хранения или импортируй предыдущий экспорт. Импорт **объединяет** записи и обновляет совпадающие ID; это не полное очищение/замещение архива.

## Важные ограничения и заметки

- Пока не подключены свои Supabase URL и key, режим остаётся демо-режимом с локальным сохранением. Для реальной синхронизации между устройствами оба значения обязательны.
- В публичном архиве все таблицы, кроме не опубликованных историй, доступны на чтение. Не записывай в них реальные пароли, адреса или чувствительную информацию.
- Максимальный размер файла для Storage настроен на 15 МБ, разрешены распространённые форматы изображений.
- Публичные Storage URL доступны всем. Если некоторые фото должны оставаться приватными, понадобится приватный bucket и подписанные временные ссылки, а не текущий публичный bucket.
- Резервная копия JSON может стать большой, если в ней много фотографий. Храни несколько копий вне сайта.
